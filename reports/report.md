### 2.2. Замечания по требованиям

#### R-01 — Возможность узнать о достижении бюджета в момент покупки

> Дать клиенту возможность узнать о достижении личного бюджета в момент покупки.  
> — _строка 23, раздел «Часть A. Новый функционал > Цели»_

- 🔴 **D-01. Противоречие с нефункциональным требованием по времени отправки** — критичный, _Корректность (29148 5.2.5 h; IEEE 830 4.3.1)_, строка 23
  - Цитата: «Дать клиенту возможность узнать о достижении личного бюджета в момент покупки.»
  - Проблема: Цель требование заявляет информирование в момент покупки, в то время как НФТ в строке 46 допускает задержку до 1 минуты после события.
  - Как исправить: Привести формулировку цели в соответствие с НФТ в строке 46.
  - _источник: модель_

- 🟠 **D-15. Неоднозначность временных рамок в формулировке «в момент покупки»** — существенный, _Однозначность (29148 5.2.5 c; IEEE 830 4.3.2)_, строка 23
  - Цитата: «Дать клиенту возможность узнать о достижении личного бюджета в момент покупки.»
  - Проблема: Формулировка «в момент покупки» не содержит конкретного временного регламента доставки уведомления.
  - Как исправить: Уточнить временной интервал доставки уведомления.
  - Тот же дефект проявляется: «можность узнать о достижении личного бюджета в момент покупки.» (строка 23) — Размытая формулировка «в момент»
  - _источник: модель_

- 🟡 см. D-31 в разделе 3 (проверка набора): 27 из 34 требований без идентификаторов

**Предлагаемая формулировка:** Дать клиенту возможность оперативно получать push-уведомление при достижении личного бюджета по карте.

#### R-02 — Поток взаимодействия компонентов при информировании о расходах

> Мобильное приложение → сервис настроек. Карточный процессинг → учёт расходов → сервис push.  
> — _строка 26, раздел «Часть A. Новый функционал > Архитектура решения»_

- 🟡 **D-37. Объединение двух независимых потоков данных в одном описании** — незначительный, _Атомарность (29148 5.2.5 e)_, строка 26
  - Цитата: «Мобильное приложение → сервис настроек. Карточный процессинг → учёт расходов → сервис push.»
  - Проблема: Требование объединяет поток сохранения настроек пользователем и поток обработки транзакций с отправкой push.
